# Skip and report Citekey collisions on case-insensitive filesystems, rather than overwriting

Reference notes are filed as `Papers/<citekey>.md`. On case-insensitive filesystems (Windows, default macOS), two distinct Citekeys differing only by case — e.g. `smith2020` and `Smith2020` — resolve to the same file. Writing both in sequence would silently overwrite the first with the second, permanently losing whatever the first Reference's note (including its freeform region) held. We instead detect the collision, skip writing the second Reference, and report it as a sync error, trading completeness for not silently destroying user data. Zotero's own Citekey uniqueness only accounts for exact-string collisions, not case-insensitive-filesystem ones, so this is a gap between what Zotero considers unique and what the target filesystem can represent as distinct files.
